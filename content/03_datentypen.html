Grundlegende Datentypen sind in C und C++ weitgehend identisch, C++ ergänzt bool und Typinferenz mit auto.

C / C++
int a = 5;            // Ganzzahl, i.d.R. 4 Byte
short s = 10;         // meist 2 Byte
long l = 100000L;     // mind. 4 Byte, oft 8
unsigned int u = 3;   // nur positive Werte
float f = 3.14f;      // einfache Genauigkeit, 4 Byte
double d = 3.14159;   // doppelte Genauigkeit, 8 Byte
char c = 'A';         // 1 Byte, ein Zeichen
const int MAX = 100;  // Konstante, danach nicht mehr änderbar

// nur C++:
bool aktiv = true;    // true/false, 1 Byte
auto x = 10;          // Typ wird vom Compiler abgeleitet -> int
Uninitialisierte Variablen: Eine lokale Variable ohne Zuweisung (int x; statt int x = 0;) enthält einen unbestimmten Wert aus dem Speicher – keine automatische 0! Das kann zu unvorhersehbarem Programmverhalten führen (z. B. ein Vergleich, der "zufällig" wahr wird). Variablen deshalb immer bei der Deklaration initialisieren.
unsigned verzichtet auf negative Werte, wodurch sich der positive Wertebereich bei gleicher Bitbreite verdoppelt. Bei 4 Byte: int reicht von -2147483648 bis 2147483647, unsigned int von 0 bis 4294967295.

Bezeichner (Variablennamen)

Für Namen von Variablen, Funktionen etc. gelten feste Regeln: erlaubt sind Buchstaben, Ziffern und _, der Name darf aber nicht mit einer Ziffer beginnen. Groß-/Kleinschreibung ist relevant (wert und Wert sind zwei verschiedene Namen), und reservierte Schlüsselwörter wie int oder class sind als Name verboten.

sizeof(typ) liefert die Größe in Byte, z. B. sizeof(int). Die genaue Byte-Größe ist plattformabhängig, char ist per Definition immer 1 Byte.

Implizite Typumwandlung (Konversionshierarchie)

Werden in einem Ausdruck unterschiedliche Datentypen gemischt, wandelt der Compiler automatisch in den "größeren" Typ um – aber nur in eine Richtung, vom kürzeren zum längeren Typ:

bool / char / short → int → unsigned int → long → unsigned long → float → double

Der umgekehrte Weg (z. B. double in int) passiert nicht automatisch verlustfrei und erfordert einen expliziten Cast (siehe unten), da sonst Nachkommastellen stillschweigend verloren gehen.

Fließkomma-Genauigkeit & Rundungsfehler

float speichert nur ca. 7 signifikante Nachkommastellen genau, double und long double ca. 15. Das führt zu sichtbaren Rundungsfehlern:

C
float r = 1000.0f / 3;
printf("%.10f\n", r);   // z.B. 333.3333435059 statt exakt 333.333333...
// Fliesskommazahlen sollten deshalb nie auf exakte Gleichheit (==) geprueft werden!

Typumwandlung (Casting)

C++
double pi = 3.9;
int i1 = (int) pi;              // C-Style-Cast -> 3 (Nachkommastellen weg)
int i2 = static_cast<int>(pi);  // bevorzugter C++-Cast -> 3

String ↔ Zahl (C++11)

Für Umwandlungen zwischen std::string und Zahlen gibt es in C++ fertige Funktionen. Sie sind klarer als atoi und melden ungültige Eingaben über Exceptions.

C++
#include <string>

std::string text = "42";
int i = std::stoi(text);              // String -> int
long l = std::stol("100000");         // String -> long
unsigned long u = std::stoul("25");   // String -> unsigned long
float f = std::stof("3.14");          // String -> float
double d = std::stod("3.14159");      // String -> double

std::string ausgabe = std::to_string(d); // Zahl -> String

}
Bei der Division zweier int wird ganzzahlig gerundet (abgeschnitten), z. B. 7 / 2 ergibt 3, nicht 3.5. Für Fließkomma-Division muss mindestens ein Operand float/double sein.
