Klassen (nur C++) bündeln Daten (Attribute) und Verhalten (Methoden) und regeln den Zugriff darauf.

C++
class Konto {
private:
    double saldo;                 // von außen nicht direkt zugreifbar

public:
    Konto(double start) : saldo(start) {}   // Konstruktor mit Initialisierungsliste
    ~Konto() {}                              // Destruktor (hier ohne Aufraeumarbeit)

    void einzahlen(double betrag) {
        saldo += betrag;
    }

    double getSaldo() const {     // const: Methode aendert das Objekt nicht
        return saldo;
    }
};

int main() {
    Konto k(100.0);      // Konstruktor wird automatisch aufgerufen
    k.einzahlen(50.0);
    cout << k.getSaldo() << endl;   // 150
}

class ist standardmäßig private, struct standardmäßig public – das ist der einzige Kernunterschied zwischen beiden in C++.

Getter/Setter-Prinzip: Attribute werden meist private gehalten und nur über öffentliche Methoden wie getSaldo() (Getter, lesen) und ggf. setSaldo(...) (Setter, schreiben) zugänglich gemacht. Das schafft eine klar definierte Schnittstelle: die Klasse kann ihre interne Umsetzung später ändern, ohne dass Code außerhalb angepasst werden muss.

this-Zeiger & statische Member

C++
class Zaehler {
private:
    int wert;
public:
    static int anzahlObjekte;   // gehoert der Klasse, nicht einem Objekt

    Zaehler() {
        wert = 0;
        anzahlObjekte++;        // this->anzahlObjekte waere ungueltig (static!)
    }
    void setWert(int wert) {
        this->wert = wert;      // this unterscheidet Member von Parameter mit gleichem Namen
    }
};
int Zaehler::anzahlObjekte = 0;   // Definition ausserhalb der Klasse noetig

Objekte erzeugen: Stack vs. Heap

C++
Konto k1(100.0);                // auf dem Stack: Konstruktor direkt aufgerufen
k1.einzahlen(50.0);             // Zugriff mit Punkt .
// k1 wird automatisch zerstoert, sobald der Gueltigkeitsbereich endet

Konto* k2 = new Konto(100.0);   // auf dem Heap: new liefert einen Zeiger
k2->einzahlen(50.0);            // Zugriff mit Pfeil -> (Kurzform fuer (*k2).einzahlen(...))
delete k2;                      // muss manuell freigegeben werden!
k2 = nullptr;                   // guter Stil: Zeiger nach delete ungueltig machen
Stack-Objekte räumen sich automatisch auf, sobald ihr Gültigkeitsbereich endet. Heap-Objekte (per new erzeugt) leben weiter, bis sie explizit mit delete freigegeben werden – sonst entsteht ein Speicherleck (siehe Abschnitt "Dynamische Speicherverwaltung").

Deklaration und Implementierung trennen (Header + .cpp)

In größeren Projekten wird eine Klasse meist auf zwei Dateien aufgeteilt: Die Header-Datei (.h) enthält nur die Klassendeklaration (Attribute, Methodenköpfe), die Implementierungsdatei (.cpp) enthält die tatsächlichen Methodenrümpfe. Der Scope-Resolution-Operator :: (den man oben schon bei Zaehler::anzahlObjekte gesehen hat) verknüpft eine Methode wieder mit ihrer Klasse.

Konto.h
// Konto.h
class Konto {
private:
    double saldo;
public:
    Konto(double start);
    void einzahlen(double betrag);
    double getSaldo() const;
};
Konto.cpp
// Konto.cpp
#include "Konto.h"

Konto::Konto(double start) : saldo(start) {}

void Konto::einzahlen(double betrag) {
    saldo += betrag;
}

double Konto::getSaldo() const {
    return saldo;
}
